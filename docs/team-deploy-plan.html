B2B ERP

팀원이 ERP를 조회하게 만드는 방법

2026년 7월 28일 정리 · 대상 시스템 b2b-sales(ERP) + b2b-erp-mcp

결론부터. 지금 필요한 건 새 도구를 만드는 일이 아닙니다. 도구는 이미 22개 만들어져 있고, 그중 11개가 캘린더 설정 게이트에 갇혀서 안 보이는 상태입니다. 그리고 팀에 뿌리기 전에 반드시 막아야 할 구멍이 있습니다.

권한이 지금 껍데기입니다. 조회 전용 등급을 만들어 두긴 했는데 실제로 검사하는 코드가 한 군데도 없습니다. 지금 상태로 팀원에게 키를 주면 조회용이라고 이름만 붙었을 뿐, 수정과 삭제까지 다 열립니다.

배포는 ERP 서버가 직접 대답하는 방식(원격)을 권합니다. 각자 노트북에 설치하는 현재 방식은 새 기능이 나올 때마다 팀원 각자가 업데이트해야 합니다. 원격으로 옮기면 ERP를 배포하는 순간 전원이 최신을 씁니다.

1. 지금 상태 진단

사실 하나. 세션 도구는 이미 있는데 갇혀 있습니다

index.js 326행에 if (calendar.isCalendarConfigured()) 조건문이 있고, 그 안에 캘린더와 아무 상관 없는 도구들까지 들어가 있습니다. 구글 OAuth 환경변수가 설정돼 있지 않으면 이 블록 전체가 등록되지 않습니다. 오늘 충북대 교육 장소를 넣을 때 MCP 도구가 아니라 API를 직접 호출해야 했던 이유가 이겁니다.

구분도구지금 보이는가
게이트 밖
항상 등록		 list_projects, get_project, update_project, create_project, create_account, list_accounts, get_dashboard, add_note, list_instructors, get_instructor, update_instructor 일부만 보임
원격 리포가 낡아서
게이트 안
캘린더 미설정 시 사라짐		 get_sessions, update_session, assign_session_instructors, add_sessions, delete_sessions, add_revenue_item, add_cost_item, sync_to_calendar, sync_preparing_to_calendar, import_sessions_from_calendar, list_calendar_events 전부 안 보임

굵게 표시한 7개는 캘린더와 무관한데 같이 갇혔습니다. 게이트를 옮기기만 하면 살아납니다.

사실 둘. 지금 도는 코드는 로컬이 아니라 GitHub 원격입니다

전역 MCP 등록이 npx -y github:chat-prompt/b2b-erp-mcp입니다. 로컬 ~/b2b-erp-mcp에는 커밋되지 않은 변경이 188줄 떠 있고(create_project, create_account, 드롭다운값 잠금 등), 그게 반영되지 않아 해당 도구들이 안 보입니다. 커밋하고 push하지 않으면 앞으로 뭘 만들어도 같은 일이 반복됩니다.

사실 셋. 권한 등급이 검사되지 않습니다

src/lib/external-auth.ts에 조회(read) · 수정(write) · 전권(admin) 3등급과 hasScope() 함수가 이미 구현돼 있습니다. 그런데 external API 라우트 24개 중 hasScope를 호출하는 곳이 0개입니다. 인증만 통과하면 등급과 무관하게 수정·삭제가 됩니다.

사실 넷. 발급되는 개인키는 전부 전권입니다

설정 화면의 API 키 발급은 이름만 받고 등급을 받지 않습니다. 데이터베이스 기본값이 admin이라 발급되는 키는 모두 전권입니다. ERP에 로그인할 수 있는 사람이면 스스로 전권 키를 뽑을 수 있습니다.

2. 배포 방식 세 가지

팀원이 클로드나 봇으로 ERP에 질문하려면, ERP와 대화하는 통로가 팀원 쪽에 있어야 합니다. 그 통로를 어디에 두느냐의 선택입니다.

방식쉽게 말하면새 기능 반영팀원이 할 일권한 관리
A. 각자 노트북에 설치
현행 stdio + 플러그인 배포		 각자 컴퓨터에 앱을 깐다 각자 업데이트해야 반영. 안 한 사람은 옛 버전 노드 설치, 플러그인 설치, 키 등록 키를 각자 파일에 보관
B. ERP 서버가 직접 대답
원격 엔드포인트 /api/mcp		 앱을 안 깔고 웹사이트에 접속한다 ERP 배포하는 순간 전원 최신 주소 한 줄 등록 ERP 화면에서 발급·폐기·등급 조정
C. 둘 다 설치는 원클릭, 실제 대답은 서버 서버 쪽은 즉시 최신 플러그인 설치 한 번 B와 같음

B를 권합니다

  • 업데이트 문제가 구조적으로 사라집니다. 지금 겪은 문제가 정확히 이겁니다. 원격 리포가 낡아서 도구가 안 보였고, 팀원 수가 늘면 이 문제가 사람 수만큼 늘어납니다.
  • 권한을 서버 한 곳에서 통제합니다. 키를 잘못 준 걸 알았을 때 ERP 화면에서 폐기 버튼만 누르면 끝입니다. 팀원 노트북에 뭐가 남아 있는지 신경 쓸 필요가 없습니다.
  • 봇도 같은 통로를 씁니다. 비투비서(슬랙봇)가 이미 ERP를 읽고 있는데, 원격으로 통일하면 관리할 곳이 하나로 줄어듭니다.
  • 단점은 만드는 작업이 필요하다는 것입니다. Next.js에 MCP 엔드포인트를 붙이는 어댑터를 쓰면 되고, 도구 정의는 지금 있는 걸 그대로 옮깁니다.

A(플러그인)를 나중에 얹는 건 언제든 됩니다. 설치 편의만 더하는 거라 B를 먼저 하고 필요해지면 C로 가는 순서가 낭비가 없습니다.

3. 이미 만들어둔 것을 어떻게 할지

버릴 건 없습니다. 역할만 정리하면 됩니다.

기존 자산현재앞으로
설정 > API 키 화면 이름만 받고 전권 키 발급. 가경님 키 1개 발급됨(사용 이력 없음) 팀 온보딩의 관문으로 승격. 등급 선택(조회 전용/수정 가능)을 추가하고 기본값을 조회 전용으로. 발급 직후 연결 명령을 복사하는 버튼까지 두면 팀원이 문서를 안 읽고도 붙습니다
PersonalApiKey 테이블 scope 칼럼 있음, 기본값 admin, 폐기·마지막사용 추적 있음 그대로 사용. 기본값을 read로 바꾸고, 이미 발급된 키는 목록을 확인해 등급을 명시적으로 지정
hasScope() 함수 구현돼 있으나 호출하는 곳 0개 external 라우트 24개에 게이트로 연결. 이게 권한의 실체가 됩니다
b2b-erp-mcp 리포 도구 22개. 캘린더 연동 포함 구글 캘린더 전용으로 축소. 캘린더는 개인 구글 계정 권한이라 서버로 옮기기 어렵습니다. ERP 데이터 조회·수정은 원격으로 이전하고, 로컬에는 캘린더 동기화만 남기는 분리가 깔끔합니다
공유키(API_SECRET_KEY) 전권. 봇과 스크립트가 공용으로 사용 유지하되 신규 배포에는 쓰지 않음. 누가 뭘 했는지 구분이 안 되므로 개인키로 이전

4. 권한 설계

등급은 이미 있는 3단계를 그대로 씁니다. 팀원 기본은 조회 전용, 수정은 신청해서 받는 구조입니다.

등급누구에게할 수 있는 일
read 팀원 기본 프로젝트·세션·거래처·강사·메모·대시보드 조회
write 신청한 담당자 조회 + 프로젝트 생성·수정, 세션 등록·수정, 메모 작성, 매출·비용 항목 추가
admin 가경님, 현철님 전부 + 삭제, 강사료 지급 처리, 세금계산서·상품권 상태 변경

도구별 등급 매핑

등급도구상태
read list_projects, get_project, get_sessions, list_accounts, list_instructors, get_instructor, get_dashboard 있음
read get_notes, get_account, list_invoices(세금계산서), list_disbursements(강사료 지급 현황), list_vouchers(상품권), get_activity(활동 이력) API는 있고 도구 없음
write add_note, update_project, create_project, create_account, add_sessions, update_session, assign_session_instructors, add_revenue_item, add_cost_item, update_instructor 있음
write assign_project_instructor(프로젝트에 강사 추가·강사료 설정), update_revenue_item, update_cost_item API는 있고 도구 없음
admin delete_sessions, delete_project, remove_instructor, update_disbursement(지급 처리), update_invoice(발행 처리), update_voucher delete_sessions만 있음

결정이 필요한 두 가지

  1. 강사 연락처를 조회 등급에 포함할지. get_instructor는 강사 휴대폰과 이메일을 반환합니다. 계좌번호와 주민번호는 API 자체가 반환하지 않으니 안전하지만, 강사 개인 연락처를 팀원 전원이 보게 할지는 판단이 필요합니다.
  2. 강사료 금액을 조회 등급에 포함할지. get_project 응답에 강사별 강사료가 들어 있습니다. 지금은 조회만 해도 다 보입니다. 가려야 한다면 응답에서 빼는 작업이 따로 필요합니다.

5. 팀원이 겪는 흐름

원격 방식으로 갔을 때 팀원이 하는 일은 이게 전부입니다.

  1. ERP에 로그인해서 설정 > API 키에서 키를 발급받습니다. 등급은 조회 전용이 기본값입니다.
  2. 화면에 나온 연결 명령을 복사해서 자기 터미널에 한 번 붙입니다.
  3. 클로드에 "충북대 교육 언제 어디서 하냐"고 물으면 답이 나옵니다.
claude mcp add --transport http b2b-erp \
  https://b2b-sales-three.vercel.app/api/mcp \
  --header "x-api-key: 발급받은키"

이 명령을 사람이 손으로 만들게 하면 반드시 사고가 납니다. 발급 화면에서 키가 채워진 상태로 복사되게 만드는 것이 온보딩의 핵심입니다.

6. 실행 순서

단계할 일고치는 곳리뷰
0단계
지금 바로		 캘린더 게이트 밖으로 세션·매출·비용 도구 7개를 이동. 커밋 안 된 188줄 정리해서 커밋 후 push b2b-erp-mcp
내 리포		 불필요
1단계 external 라우트 24개에 등급 게이트 연결. 조회 키는 GET만 통과. 발급 화면에 등급 선택 추가, 기본값 조회 전용으로 변경 b2b-sales
팀 리포		 필요
2단계 원격 MCP 엔드포인트 /api/mcp 추가. 도구 정의 이전 + 빠진 조회 도구 6개 신규 b2b-sales
팀 리포		 필요
3단계 발급 화면에 연결 명령 복사 버튼, 팀원 안내 한 장, 필요하면 플러그인 등록 b2b-sales + 플러그인 가벼움

0단계는 팀 배포와 독립적입니다. 내 리포만 건드리고, 끝나면 저와 이재혁님이 오늘부터 세션 도구를 쓸 수 있습니다. 1단계부터는 팀 리포(chat-prompt/b2b-sales) 수정이라 PR과 리뷰가 필요하고, 특히 권한 게이트는 잘못 걸면 봇과 기존 스크립트가 멈추므로 기존 공유키가 계속 통과하는지 확인하면서 가야 합니다.

7. 리스크

  • 권한 게이트가 기존 연동을 끊을 수 있습니다. 비투비서 봇, 인바운드 자동초안, 로컬 스크립트가 모두 공유키로 붙어 있습니다. 공유키는 전권이라 원칙적으로는 통과하지만, 게이트를 넣는 순서를 잘못 잡으면 조용히 실패합니다. 1단계에서 실제 호출로 확인해야 합니다.
  • 조회 전용이라고 안심할 수 없는 것이 하나 있습니다. 조회만으로도 강사료, 예상 매출, 마진이 다 보입니다. 팀원에게 이 숫자를 보여줄 것인지가 권한 등급보다 먼저 정해질 문제입니다.
  • 전권 키가 이미 발급돼 있을 수 있습니다. 1단계에서 기존 키 목록을 확인해 등급을 정리해야 합니다.

확인이 필요한 것: 0단계를 지금 진행할지, 그리고 4번의 두 가지 결정(강사 연락처·강사료 금액을 조회 등급에 포함할지). 1단계와 2단계는 팀 리포 수정이라 착수 전에 컨펌을 받겠습니다.
